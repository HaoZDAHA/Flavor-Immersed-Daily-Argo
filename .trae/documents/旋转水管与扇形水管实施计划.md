# 旋转水管 与 扇形水管 实施计划

## 一、目标（Summary）

在农业耕种横幅下新增两个方块，作为水管系统的末端洒水器：

1. **旋转水管 `rotating_water_pipe`**：接在管网末端（可隔着**一个固体方块**），管网通水后播放 Blockbench 导出的 `round` 动画（绕竖轴每 2 秒转一圈），并在**喷嘴位置随模型一起旋转**喷出水的粒子。
2. **扇形水管 `sector_water_pipe`**：接在管网末端（同样可隔一个固体方块），通水后在**正前方水平区域呈扇形**喷出水的粒子。

两者都要：
- 接进既有水管系统（`WaterPipeBlock` 管网）；
- 兼容金坷垃（`DosingTubeBlock` 的 `FERTILIZED` 催熟加成）；
- 复用既有灌溉逻辑（把落点附近的耕地湿度顶满）。

## 二、现状分析（Current State Analysis）

### 2.1 水管系统（[WaterPipeBlock.java](file:///c:/Users/15244/IdeaProjects/flavor_immersed_daily_argo/src/main/java/com/flavor_immersed_daily_argo/block/WaterPipeBlock.java)）
- `isNetwork(BlockState)`（L129）：目前只认 `WaterPipeBlock` 与 `DosingTubeBlock`。**新方块要接进管网必须在此登记。**
- `refreshNetwork` / `refreshOne`（L195-L274）：从 origin 做 6 邻接 BFS，遍历所有 `isNetwork` 方块，判断能否够到（a）泡水的 `WaterPumpBlock` → `FILLED`，（b）生效的 `DosingTubeBlock` → `FERTILIZED(true)`；写回时用 `Block.UPDATE_CLIENTS`（故意不发邻块更新，避免递归）。对每个 `isNetwork` 且带 `FILLED` 属性的方块都会写回。
  - **关键含义**：只要新方块带 `FILLED`/`FERTILIZED` 属性并加入 `isNetwork`，**直接相邻**时就会被自动刷成正确状态；而**隔一格**时 BFS 走不过去，新方块必须自己探测。
- `FILLED` / `FERTILIZED` 是 public 的 `BooleanProperty`（L69/L79），可被新方块直接复用（`DosingTubeBlock` 已复用 `FILLED`）。
- 灌溉相关（L332-L437）：`IRRIGATE_INTERVAL=20`、`IRRIGATE_RADIUS_H=4`、`IRRIGATE_RADIUS_V=2`、`FERTILIZE_CHANCE=0.05F`；`irrigate(ServerLevel,BlockState,BlockPos)` 私有，内部 `landing()` 求抛物线落点后把 ±4/±2 内 `FarmBlock` 湿度顶满、`FERTILIZED` 时 `tryFertilize`。
- 末端喷水：`isSpraying` = `FILLED && bitCount(SHAPE)==1`；敞口方向 = 唯一接口的反方向。（**即：若末端水管旁边接上了新方块并被记为一个连接，该管就不再是单口，会停止自行喷水** —— 这正是我们要的“洒水器接管末端”。）
- `animateTick`（L463）用 `ParticleTypes.SPLASH` / `FALLING_WATER` / `HAPPY_VILLAGER`，客户端粒子范式可直接照搬。

## 三、方案总览与关键决策（Assumptions & Decisions）

| 决策点 | 选择 | 理由 |
|---|---|---|
| 与管网的“连接”方式 | **两个洒水器都加入 `WaterPipeBlock.isNetwork`**：直接相邻时末端水管会长出管臂插进洒水器（该管因此不再是单口，停止自行喷水），状态由 `refreshOne` 自动刷新 | 符合“接在水管系统末尾”的语义，避免末端水管朝洒水器渗水花；复用既有刷新机制 |
| “中间隔一个固体方块” | 洒水器**四邻没有管网时**，自行在 6 方向 **距离 2** 探测：中间那格必须是**有碰撞箱的固体方块**、外圈是同管网方块，则按外圈管网的 `FILLED`/`FERTILIZED` 同步自身状态（每 20 刻一次） | BFS 走不过固体方块，必须自探测；与“已直接接入”互斥，避免两套机制打架 |
| 未要求 `WATERLOGGED` | **不加** | 用户未要求；洒水器不是埋管，无需含水 |
| 通用逻辑归属 | 抽象基类 `WaterSprinklerBlock` 持有公共逻辑，两个子类只加各自差异（渲染方式 / FACING / 粒子形状） | 遵循“同类方块用一个通用类”的既有偏好，同时不牺牲清晰度 |
| 灌溉复用 | 在 `WaterPipeBlock` 中抽出 `public static void irrigateArea(ServerLevel, BlockPos center, boolean fertilized, int rH, int rV)`，`IRRIGATE_INTERVAL` 改 public；原管道的 `irrigate(...)` 改为调用它 | 三处（管道 / 旋转 / 扇形）共用一个浇灌工具，参数一致 |
| 贴图 | 复制 `畜牧/rotating_water_pipe/rotating_water_pipe.png` → `textures/entity/rotating_water_pipe.png` 与 `textures/block/rotating_water_pipe.png`（后者供扇形静态模型用，遵循其 json 的引用）；两个 16×16 分别复制为 `textures/item/rotating_water_pipe.png`、`textures/item/sector_water_pipe.png` | 素材只给了一张 64×64 方块贴图，扇形 json 明确引用 `block/rotating_water_pipe` |
| 旋转动画驱动 | 渲染器与粒子**共用同一个相位公式** `phase = (gameTime % 40) / 40 * 360`；渲染器 `setArmAngle(-phase)`（对齐导出动画的负向 0→-360），粒子世界角取 `+phase` | 两者同源，方向由导出动画推得：模型空间 yRot 经 `scale(-1,-1,1)` 后在世界上反向，故 -phaseRad(模型) ⇒ +phase(世界) |
| 扇形朝向 | `FACING` 水平四向，喷洒沿 FACING 正前方 | 用户明确“前方水平区域扇形” |
| 隔一格时末端水管仍会朝固体方块渗一点水花 | **接受**（撞到固体方块立刻停下，落点就在墙里，无实际影响） | 避免为极端情况增加复杂度 |

## 四、具体改动（Proposed Changes）

### 4.1 新增：`block/WaterSprinklerBlock.java`（抽象基类）
路径：`src/main/java/com/flavor_immersed_daily_argo/block/WaterSprinklerBlock.java`

- `public abstract class WaterSprinklerBlock extends Block`。
- 状态属性：`public static final BooleanProperty FILLED = WaterPipeBlock.FILLED;`、`FERTILIZED = WaterPipeBlock.FERTILIZED`；`createBlockStateDefinition` 加入两者，默认都 false。
- `protected abstract VoxelShape collisionShape();`
  - `getShape` 返回 `Shapes.block()`（好瞄准）；`getCollisionShape` 返回 `collisionShape()`。
- `protected abstract void irrigateAt(ServerLevel level, BlockState state, BlockPos pos);`
- `protected abstract void emitSpray(Level level, BlockPos pos, BlockState state, RandomSource random);`
- `getStateForPlacement`：`defaultBlockState().setValue(FILLED,false).setValue(FERTILIZED,false)`（子类叠加 FACING）。
- `onPlace`：若 `!level.isClientSide && !WaterPipeBlock.isNetwork(oldState)` → `WaterPipeBlock.refreshNetwork(level,pos)` 且 `level.scheduleTick(pos,this,WaterPipeBlock.IRRIGATE_INTERVAL)` 启动节拍链。
- `onRemove`：`!level.isClientSide && !WaterPipeBlock.isNetwork(newState)` → `WaterPipeBlock.refreshNetwork(level,pos)`。
- `updateShape`：服务端 `WaterPipeBlock.refreshNetwork(realLevel,pos)`（同 `DosingTubeBlock` 写法），返回 `super.updateShape(...)`。
- `tick(...)`：`serverTick(level,pos,state)` 后 `level.scheduleTick(pos,this,WaterPipeBlock.IRRIGATE_INTERVAL)`。
- `randomTick(...)`：若 `!level.getBlockTicks().hasScheduledTick(pos,this)` → `serverTick(...)` + 重新排程（区块重载兜底，与 `WaterPipeBlock` 同款）。
- `static void serverTick(Level level, BlockPos pos, BlockState state)`：
  1. 扫 6 邻：若有 `WaterPipeBlock.isNetwork(...)` 则 `attached=true`（交给 `refreshOne`）。
  2. 若 `!attached`：对每个方向 `d`，若 `mid=pos.relative(d)` 是固体（`!level.getBlockState(mid).getCollisionShape(level,mid).isEmpty()`）且 `pos.relative(d,2)` 是管网方块 → 收集其 `FILLED`/`FERTILIZED`；随后把自身状态写为 `FILLED=found`、`FERTILIZED=found && foundFert`，改变时用 `Block.UPDATE_CLIENTS` 写回。
     - 注意：`mid` 若本身是管网方块则已被第一步判为 attached，进入不到这里。
  3. 重新读取自身状态，若 `FILLED` → `irrigateAt(level, now, pos)`。
- `animateTick`：若 `state.getValue(FILLED)` → `emitSpray(level,pos,state,random)`。

### 4.2 新增：`block/RotatingWaterPipeBlock.java`
- `extends WaterSprinklerBlock implements EntityBlock`。
- 常量：`public static final float TURN_TICKS = 40.0F;`（2 秒）、`NOZZLE_RADIUS = 0.375D`、`NOZZLE_HEIGHT = 0.5625D`。
- `public static float phaseDegrees(Level level)`：`(level.getGameTime() % TURN_TICKS) / TURN_TICKS * 360F`（渲染器与粒子共用；渲染器可另传 partialTick 做平滑）。
- `codec()` = `simpleCodec(RotatingWaterPipeBlock::new)`。
- `getRenderShape` → `RenderShape.ENTITYBLOCK_ANIMATED`。
- `collisionShape()` → `Block.box(2.0,0.0,2.0,14.0,11.0,14.0)`（贴合底板+立柱+臂）。
- `newBlockEntity` → `new RotatingWaterPipeBlockEntity(pos,state)`。
- `irrigateAt` → `WaterPipeBlock.irrigateArea(level, pos, state.getValue(FERTILIZED), 4, 2)`。
- `emitSpray`：`float p = phaseDegrees(level); double rad = Math.toRadians(p);`
  - 两个喷嘴（`dir = +1 / -1`）：`ox = cos(rad)*NOZZLE_RADIUS*dir`、`oz = -sin(rad)*NOZZLE_RADIUS*dir`，位置 `(x+0.5+ox, y+NOZZLE_HEIGHT, z+0.5+oz)`；
  - 每个喷嘴 `addParticle(SPLASH, …, ox*0.15, 0.05, oz*0.15)`；随机再来 0~1 个 `FALLING_WATER`（向外/向下少许）；
  - `FERTILIZED` 时按 `0.35F` 概率加 `HAPPY_VILLAGER`（同水管）。

### 4.3 新增：`block/SectorWaterPipeBlock.java`
- `extends WaterSprinklerBlock`。
- `public static final DirectionProperty FACING = BlockStateProperties.HORIZONTAL_FACING;`
- `public static final float FAN_ANGLE_DEGREES = 60.0F;`、`FAN_RADIUS = 3.0D`、`SPRAY_HEIGHT = 0.6D`。
- `createBlockStateDefinition` 追加 `FACING`；默认 `FACING=NORTH`。
- `getStateForPlacement`：先取基类状态；若四邻存在管网方块 → `FACING = 反方向`（背对管网，正面喷向远端）；否则 `FACING = context.getHorizontalDirection().getOpposite()`。
- `rotate`/`mirror` 就地旋转 FACING。
- `getRenderShape` 用默认 `MODEL`（静态方块模型）；`codec()`。
- `collisionShape()` → `Block.box(3.0,0.0,3.0,13.0,11.0,13.0)`。
- `irrigateAt` → `WaterPipeBlock.irrigateArea(level, pos.relative(state.getValue(FACING), 2), state.getValue(FERTILIZED), 3, 2)`（把浇灌方块前移，覆盖“前方”）。
- `emitSpray`：取 `f = state.getValue(FACING)`，本刻采样 4 次：
  - `spread = (random.nextFloat()-0.5F) * toRad(FAN_ANGLE_DEGREES)`；`c=cos(spread), s=sin(spread)`；
  - 方向 `vx = f.stepX*c - f.stepZ*s`、`vz = f.stepX*s + f.stepZ*c`；半径 `r = 0.5 + random.nextDouble()*FAN_RADIUS`；
  - 位置 `(x+0.5+vx*r, y+SPRAY_HEIGHT, z+0.5+vz*r)`，速度 `(vx*0.06, 0.02, vz*0.06)` 用 `SPLASH`；偶发 `FALLING_WATER`；
  - `FERTILIZED` 时 0.35 概率 `HAPPY_VILLAGER`。

## 五、验证步骤（Verification）

1. 编译与数据生成（沙箱外执行）：
   - `.\gradlew.bat runData`（生成 `models/item/rotating_water_pipe.json`、`models/item/sector_water_pipe.json` 与 en_us 语言键）
   - `.\gradlew.bat compileJava`
   - 两者均需 `dangerouslyDisableSandbox: true`。
2. 静态自检：
   - 新增/修改文件无编译错误（import 齐全）；
   - blockstate 引用的模型名与落盘文件名一致；贴图路径与 `textures/...` 一致；
   - 掉落表 `name` 与注册名一致。
3. 运行期清单（进游戏手动确认，作为交付说明留给用户）：
   - 水泵埋水 + 一截水管，末端放**旋转水管**：末端水管停止自行喷水、旋转水管开始转并喷洒；耕地被浇湿。
   - 中间夹**一个固体方块**再接旋转水管：仍能转、能喷、能浇。
   - **扇形水管**：朝向正前方的水平扇形喷水；旋转到面向不同方向（FACING）时喷向随之改变。
   - 管网中串一个**加料阀**并投金坷垃：两个洒水器喷洒时出现 `HAPPY_VILLAGER`，落点作物被随机催熟。
   - 破坏洒水器与管网：状态随之清除；掉落物正确。
4. 视觉校准项（若不匹配再微调，属实现期一次调整）：
   - 粒子旋转方向与模型臂的转向是否一致（如有相反，将 `phaseDegrees` 取负同时用于渲染器与粒子——两处同源，改一处即可）；
   - 粒子喷嘴半径/高度（`NOZZLE_RADIUS=0.375`、`NOZZLE_HEIGHT=0.5625`）与模型臂端是否贴合；
   - 扇形角度（`FAN_ANGLE_DEGREES=60`）、半径（`FAN_RADIUS=3`）、高度（`SPRAY_HEIGHT=0.6`）手感。

## 六、影响面与风险

- 修改 `WaterPipeBlock.isNetwork` 属**全局行为**：已存在的存档里，洒水器一旦出现就会被纳入管网；不会影响现有水管/水泵/加料阀的结构（只是新增一类可连通方块）。
- `irrigateArea` 抽取为重构，管道原有灌溉行为与参数保持不变（回归风险低）。
- 若扇形方块“正面”与模型朝向不一致，只需调整 `sector_water_pipe.json` 各 facing 的 `y` 值（不涉及代码）。
