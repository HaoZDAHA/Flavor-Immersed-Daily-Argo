## 2. 鱼护 `fish_protection`（方块 · 可含水 · 连接变体）

**模型分析**（`畜牧/fish_protection/`）：4 个 JSON 对应「围栏保留面数」
| 文件 | 形态 | blockstate 值 |
| --- | --- | --- |
| `fish_protection.json` | 四面围栏 + 底 + 顶沿 | `connected=0`（四周无相邻鱼护） |
| `fish_protection1.json` | 保留北/东两面 | `connected=1` |
| `fish_protection2.json` | 仅保留北面 | `connected=2` |
| `fish_protection3.json` | 仅底面 | `connected=3`（三面及以上相邻） |

**新增文件**：
- `fishing/FishProtectionBlock.java` — `extends BaseEntityBlock implements SimpleWaterloggedBlock`
  - 状态：`WATERLOGGED`(bool) + `CONNECTED`(int 0..3)
  - `getStateForPlacement`：读取流体 → `WATERLOGGED`
  - `updateShape`：相邻方块变化 → 重算 `CONNECTED`（统计水平四向相邻鱼护数量：0→0，1→2，2→1，≥3→3）
  - `getShape`：整格（增大鼠标指示箱）；`getCollisionShape`：贴合矮箱（约 `(0,0,0)-(16,17/16,16)` → 取 `1/16..15/16`、高 17/16 内收）
  - `getRenderShape` = `MODEL`；`propagatesSkylightDown` / `noOcclusion`
  - `useWithoutItem`：空手右键 → 取出最新放入的一条鱼（转为实体抛出 / 物品），见下
- `fishing/FishProtectionBlockEntity.java` — 存 `List<CompoundTag>`（活体快照）或 `List<ItemStack>`，容量上限（如 6 条）
- 注册：`ModBlocks`、`ModItems`、`ModBlockEntities`、创造栏、`zh_cn` / `ModLangs`

**资源**：
- `blockstates/fish_protection.json`：`connected` × 4 变体 → 对应模型
- `models/block/fish_protection{,1,2,3}.json`：从 `畜牧/fish_protection/*.json` 复制，`textures."0"` 改为 `flavor_immersed_daily_argo:block/fish_protection`
- `textures/block/fish_protection.png`：`畜牧/fish_protection/fish_protection.png`
- `models/item/fish_protection.json`：`parent` = `models/block/fish_protection`（或独立手持模型，待确认）
- `textures/item/fish_protection.png`：`畜牧/fish_protection.png`
- `loot_table/blocks/fish_protection.json`

**钓鱼接入点**（[ModFishingHook.java](file:///c:/Users/15244/IdeaProjects/flavor_immersed_daily_argo/src/main/java/com/flavor_immersed_daily_argo/fishing/ModFishingHook.java#L538-L554) `giveCatch`）：
- 在「持抄网 + 有实体」分支（L538-554）内，先搜索钩点/玩家周围半径 R（默认 8 格）内最近的鱼护；
  - 命中 → 把活体实体生成到鱼护方块中心（不飞向玩家），并写入鱼护 BlockEntity 记账；
  - 未命中 → 维持现状（飞向玩家）。
- 「掉落物品」分支（L555-573）**不改**（交给需求 3 的钓鱼箱处理）。

## 3. 钓鱼箱 `fishing_box`（方块 · 朝向 · 36 格容器 UI）

**模型分析**：`畜牧/fishing_box/fishing_box.json`，箱体约 `x0-16, y0-9, z3-13`（1/16 单位）。

**新增文件**：
- `fishing/FishingBoxBlock.java` — `extends BaseEntityBlock`
  - 状态：`FACING`(north/south/east/west)，默认 4 向旋转
  - `getShape` / `getCollisionShape`：按模型生成盒体（约 `(0,0,3)-(16,9,13)`，按 `FACING` 做 y 旋转）；`getShape` 可略放大
  - `useWithoutItem`：`serverPlayer.openMenu(be, buffer -> buffer.writeBlockPos(pos))`
  - `onRemove` / `getDrops`：把 36 格内容物随方块掉落
- `fishing/FishingBoxBlockEntity.java` — `extends BlockEntity implements MenuProvider`，内含 `SimpleContainer(36)`
- `fishing/FishingBoxMenu.java` — `extends AbstractContainerMenu`，36 格箱格 + 玩家 36 格
  - 客户端构造器读 `extraData.readBlockPos()`
  - `stillValid`：`MAX_USE_DISTANCE_SQR = 64.0D`
  - 布局：箱格 4 行 × 9 列（`IMAGE_WIDTH=176`，高度按 4 行重算）
- `fishing/FishingBoxScreen.java` — 复用本项目「不贴图 + `gui.fill` 暗底」风格（参照 `ChickenCoopScreen`）
- 注册：`ModMenus`（`IMenuTypeExtension.create(FishingBoxMenu::new)`）、`flavor_immersed_daily_argoClient.registerScreens`、方块 / 物品 / 方块实体 / 创造栏

**资源**：
- `blockstates/fishing_box.json`：`facing` × 4 → 同一模型 4 种 y 旋转
- `models/block/fishing_box.json`：`畜牧/fishing_box/fishing_box.json`，`textures."0"` → `...:block/fishing_box`
- `textures/block/fishing_box.png`：`畜牧/fishing_box/fishing_box.png`
- `models/item/fishing_box.json`：`parent` 指向方块模型（用 `FIDItemModelProvider.withExistingParent`）
- `textures/item/fishing_box.png`：`畜牧/fishing_box.png`
- `loot_table/blocks/fishing_box.json`

**钓鱼接入点**（`giveCatch` 的 L555-573 物品分支）：
- 玩家**未**持抄网时，先搜索钩点/玩家周围半径 R 内最近的钓鱼箱；
  - 命中 → 把 `drop` 尝试塞入其 `SimpleContainer`（`ItemStack` 合并 / 找空位），失败再落为物品实体；
  - 未命中 → 维持现状掉落。

## 4. 杆秤 `steelyard`（工具 · JSON 驱动称重 GUI）

**模型分析**：`畜牧/steelyard/steelyard.json`，**无 `texture_size`**，`textures` 键为中文（`秤1/秤2/秤3`），必须重命名。

**新增文件**：
- `item/SteelyardItem.java` — `use` → 打开 GUI（服务端 `player.openMenu`，携带手持物所在的位置信息或直接把 ItemStack 放菜单容器）
- `fishing/WeighingTypeData.java` — 仿 `FishingHandbookData` 的 `SimpleJsonResourceReloadListener`
  - `FOLDER = "weighing_types"`；单例；`apply`（服务端）/ `applyFromJson`（客户端重建）
- `fishing/WeighingTypeEntry.java`（record）— `category` + `Map<ResourceLocation, WeightSpec>`；`WeightSpec(mean, sigma, min, max, unit)`
- `fishing/WeighingDataSyncPacket.java` — 仿 `FishingDataSyncPacket`，`OnDatapackSyncEvent` 下发
- `fishing/SteelyardMenu.java` / `SteelyardScreen.java` — 1 个称重槽 + 结果显示
- 注册：`ModItems`、`ModMenus`、创建栏、`flavor_immersed_daily_argoClient.registerScreens`、数据监听（`FishingDataEvents` 内追加）

**数据文件**：`data/flavor_immersed_daily_argo/weighing_types/freshwater_fish.json`
```jsonc
{
  "category": "淡水鱼类",
  "unit": "克",
  "default": { "mean": 500, "sigma": 150, "min": 80, "max": 3000 },
  "items": {
    "flavor_immersed_daily_argo:raw_grass_carp":    { "mean": 1200, "sigma": 350 },
    "flavor_immersed_daily_argo:raw_crucian_carp":  { "mean": 250,  "sigma": 90  },
    ...
  }
}
```
- 取重算法：以 `mean` / `sigma` 生成正态随机（Box-Muller 或 `random.nextGaussian()`），并按 `[min, max]` 截断 / 重采样，保证合理区间。
- **本模组生淡水鱼清单（17 种，`habitat = fresh`）**：
  `raw_grass_carp`(草鱼)、`raw_black_carp`(黑鲤)、`raw_bighead_carp`(鳙)、`raw_chinese_carp`(鲤)、`raw_crucian_carp`(鲫)、`raw_silver_carp`(鲢)、`raw_mandarin_fish`(鳜/扁鱼)、`raw_black_fish`(黑鱼/乌鳢)、`raw_catfish`(鲶)、`raw_loach`(泥鳅)、`raw_tench`(丁鱥)、`raw_bass`(鲈)、`raw_tilapia`(罗非)、`raw_goby`(虾虎)、`raw_redfin`(赤眼鳟)、`raw_pleco`(清道夫)、`raw_rectum`(直肠鱼)。
- 后续可加分类：海鱼类、甲壳类、软体类（结构已支持）。

**资源**：
- `models/item/steelyard.json`：从素材复制，补 `texture_size: [16,16]`，`textures` 重命名为 `flavor_immersed_daily_argo:item/steelyard1/2/3`
- `textures/item/steelyard1.png`、`steelyard2.png`、`steelyard3.png`（源：`畜牧/steelyard/` 内对应贴图）
- `textures/item/steelyard.png`：`畜牧/steelyard.png`（背包图标，可选作为 `layer0`）

## 5. 竿架 `rod_pod`（方块 · 渲染鱼竿 · 咬钩提醒 · 便捷遛鱼）

**模型分析**：`畜牧/rod_pod/rod_pod.json`，`texture_size [32,32]`，5 个 elements（立柱 + 斜插竿托 + 十字底脚），无 `display` 段 → 方块模型。

**新增文件**：
- `fishing/RodPodBlock.java` — `extends BaseEntityBlock`，`FACING` 或模型自带方向（**待确认**）
  - `useItemOn`：手持南山钓竿 → 存入 BlockEntity；空手右键 → 取回钓竿并可进入遛鱼
  - 掉落随内容物
- `fishing/RodPodBlockEntity.java` — 存 `ItemStack rod`（含抛竿状态）、关联的 `ModFishingHook` 引用/坐标
- `fishing/RodPodRenderer.java` — `BlockEntityRenderer`，用 `ItemRenderer` 渲染钓竿物品模型（`thirdperson` / `fixed` 变换）
- `fishing/RodPodEvents.java` — 监听咬钩事件
- 注册：方块 / 物品 / 方块实体 / 方块实体渲染器（`EntityRenderersEvent.RegisterRenderers`）/ 创造栏

**行为**：
1. 玩家持南山钓竿抛竿后，对竿架右键 → 钓竿移到竿架（玩家手上清空），鱼钩进入「托管」状态。
2. 有鱼上钩时，向**最近的玩家**发送提醒（actionbar 文本 + 声音）。
3. 该玩家右键竿架 → 取回钓竿，并把 `ModFishingHook` 的遛鱼阶段转移给该玩家（`startFight(player)`），直接进入遛鱼环节。

**接入点**：
- `ModFishingHook` 增加「托管玩家」字段（`owner` 可为空），`tick` 咬钩时若 `owner == null` 则向最近玩家提醒；遛鱼启动时把 `fighting` 阶段的收杆判定者从原玩家改为取杆玩家。
- 需核对现有 `startFight` / `tickFight` 对 `player` 的依赖点（在实现前精读 L100-490）。

**资源**：
- `blockstates/rod_pod.json`、`models/block/rod_pod.json`（`textures."0"` → `...:block/rod_pod`）
- `textures/block/rod_pod.png`、`textures/item/rod_pod.png`（`畜牧/rod_pod.png`）
- `models/item/rod_pod.json`、`loot_table/blocks/rod_pod.json`

## 6. 需要确认的关键假设

1. **鱼护承接方式**：默认「活体实体生成在鱼护方块中心，并被方块限制在箱内；空手右键取出」。另一种方案是「只存为物品/数据组件，右键取出实体」。→ 采用哪种？
2. **鱼护连接判定**：默认按「水平四向相邻鱼护数量」映射 `connected=0/1/2/3`（0→0、1→2、2→1、≥3→3）。是否符合素材设计意图？
3. **钓鱼箱 36 格布局**：默认 4 行 × 9 列（类似箱子的 3 行扩为 4 行），非「27+9」。确认？
4. **钓鱼箱 / 鱼护的作用半径**：默认 8 格（以钩点为中心）。是否需要改成以玩家为中心？
5. **杆秤单位与分布**：默认单位为「克」，每条鱼给 `mean` / `sigma`，正态采样后截断到 `[min, max]`。是否需要「斤」或更贴近现实的重量区间？
6. **竿架方向**：`rod_pod.json` 无 `display` 且斜插角度是固定朝北（`axis: x` 旋转），是否需要加 `FACING`（4 向旋转）、还是固定单朝向？
7. **竿架取杆范围**：「最近的玩家」默认取竿架半径 16 格内最近的玩家；若无人则保持托管。确认？
