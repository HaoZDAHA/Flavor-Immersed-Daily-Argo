# 宠物窝（Pet Nest）实现方案

## 一、背景与目标

需求来源（用户原话）：注册「宠物窝」方块，放在**畜牧**横幅，使用 `畜牧/宠物窝/pet_nest.png`（方块贴图）与 `畜牧/pet_nest.png`（手持贴图）。驯服后的猫和狗会寻路绑定一个宠物窝；绑定后该动物死亡，次日会复活在窝上。绑定过的猫狗除「跟随」「蹲下」外，增加第三种**游荡模式**：在窝周围几个区块内游荡，附近有老鼠时迅速索敌。

预期结果：一个可放置的装饰性功能方块 + 一套宠物行为扩展，全部复用原版 `Cat`/`Wolf`，**不新增实体**。

---

## 二、关键设计决策（含 7 条假设，请确认）

调研中发现 4 个必须绕开的硬约束（已核对反编译源码 `build/moddev/artifacts/neoforge-21.1.219-sources.jar`）：

| 约束 | 结论 |
|---|---|
| `Cat.setCollarColor` / `Wolf.setCollarColor` 是 **private** | 不能直接调用。复原项圈色只能走 NBT 整体重建：`EntityType.create(tag, level)`（`readAdditionalSaveData` 对 Cat/Wolf 是 public） |
| `GoalSelector` 优先级「号小者胜」，且被顶掉的 goal 必须可打断 | 单个 goal **无法**同时压住 `FollowOwnerGoal(6)` 又让位给攻击 goal（要求 priority 既 <6 又 >9，矛盾）→ 游荡模式下必须**移除** `FollowOwnerGoal` |
| 原版优先级（已核实） | Cat：Sit 2 / FollowOwner 6 / OcelotAttack 9 / Stroll 11；Wolf：MeleeAttack 5 / FollowOwner 6 / Stroll 8 |
| `EntityJoinLevelEvent` 区块读档时也会触发 | 挂 goal 必须**幂等去重**（顺带修掉 `MouseSpawning` 现有的重复累积隐患） |

**7 条假设（按默认执行，如需改动请指出）**

1. **模式轮换**：空手右键宠物循环 `跟随 → 蹲下 → 游荡 → 跟随`，动作栏中文提示；手中持物（染料 / 食物 / 狼铠）仍走原版交互。
2. **未绑定宠物窝的宠物不允许进入游荡模式**，提示后退回跟随。
3. **绑定由「窝」主动完成**：窝每约 2 秒扫描 32 格内已驯服的猫 / 狗，把它们引过来安家（行为与「宠物自己找窝」等效，但复用项目既有的 `ChickenCoopBlockEntity` 扫描范式，代价更低）。
4. **游荡半径 24 格**（1.5 区块），超过 32 格回家；**追鼠半径 48 格**（3 区块）。
5. **「次日复活」**按主世界 `overworld.getDayTime() / 24000L` 的日计数，与 `ForestryNetworkManager` 口径一致。
6. **一个窝只住一只宠物**；窝被拆除则解绑，未到期的复活快照一并丢弃。
7. 死后复活**沿用原主人 / 自定义名 / 项圈色**，但分配**新 UUID**（避免与已死实体撞号）。

## 五、核心逻辑

### A. 游荡模式

`PetWanderGoal`：只占 `Flag.MOVE`（不占 `LOOK`，让原版 `LookAtPlayerGoal` 继续跑，宠物显得有生气）。
- 优先级取 **Cat 10 / Wolf 7**：既能压住 `Stroll`（11/8），又会被 `OcelotAttack(9)` / `MeleeAttack(5)` 顶掉 → **捕鼠与攻击动作完全复用原版**，无需自己写攻击。
- `canUse()` = `mode == WANDER && 已绑定窝`；到点就 `navigation.moveTo(窝 ± 随机 24 格, 1.0)`；水平距离 > 32 格直接回窝。

进入 WANDER 时移除 `FollowOwnerGoal`，回到 FOLLOW/SIT 时按原版数值加回（**数值抄自 1.21.1 `Cat`/`Wolf#registerGoals`，写进常量并注明来源**）：
- Cat：`addGoal(6, new FollowOwnerGoal(cat, 1.0, 10.0F, 5.0F))`
- Wolf：`addGoal(6, new FollowOwnerGoal(wolf, 1.0, 10.0F, 2.0F))`

加之前先扫 `getAvailableGoals()` 判重，避免读档累积。

### B. 模式轮换

`PlayerInteractEvent.EntityInteract`（**不是** `EntityInteractSpecific`）：取消后 `Mob.mobInteract` 不执行，原版 `setOrderedToSit(!isOrderedToSit())` 被彻底绕开，无冲突；两侧都 `setCanceled(true)` 避免客户端本地跑一遍原版逻辑。过滤条件：是 `Cat`/`Wolf`、`isTame()`、`isOwnedBy(玩家)`、`itemStack.isEmpty()`。

### C. 绑定（窝侧扫描）

照抄鸡窝 `updatePerch` 的范式：
- 扫描盒 `new AABB(pos).inflate(32, 8, 32)`，间隔 40 tick，并用 `random.nextInt(40)` 错开相位。
- 候选：`isTame()` 的 `Cat`/`Wolf`，且未被其它窝认领（宠物持久化数据里的窝坐标 ≠ 本窝坐标）。
- 抢占互斥：窝只有一个 `@Nullable UUID pet` 字段，服务端单线程 tick 内写一次，天然互斥，**无需锁**。
- 绑定后每 20 tick `pet.getNavigation().moveTo(窝中心, 1.0)` 直到水平距离 < 1.5 格（**不要** `setNoAi(true)`，与鸡窝不同）。
- 每 tick 用 `serverLevel.getEntity(uuid)` 检查存活，失效则清窝字段 + 清宠物侧键 + 模式回 FOLLOW。
- 维度写入 `NEST_DIM`，与 `level.dimension().location()` 比对，跨维度视为未绑定。

### D. 死亡 → 次日复活

**捕获**（`LivingDeathEvent`，GAME bus）：把宠物序列化成一个子 tag（`"id"` = 实体类型注册名，`Owner`、`CustomName`、`CustomNameVisible`、`CollarColor`、`variant`），**故意不写 `"UUID"`**；连同死亡当日 `Day` 一起存入窝的 BE。

**还原**（窝 `serverTick`，`currentDay > deathDay`）：
```java
Entity e = EntityType.create(pendingPetTag, level).orElse(null);  // 静态方法，自动走 load()
if (e instanceof TamableAnimal pet) {
    pet.setPersistenceRequired();
    pet.moveTo(cx, cy, cz, level.random.nextFloat() * 360.0F, 0.0F);
    level.addFreshEntity(pet);
    PetNestFolk.bind(pet, worldPosition, level.dimension());
    PetNestFolk.setMode(pet, PetMode.WANDER);
}
```
这一步同时恢复 `Owner`（`TamableAnimal` 读档分支会自动 `setTame`）、`CustomName`、`CollarColor`、`variant` —— 是绕过 private `setCollarColor` 的唯一正规路径（替代方案是引入 access transformer，`build.gradle:53` 目前注释着，不建议为一个方法引入新基础设施）。
有快照期间该窝**保留占位**，不接受新宠物，避免新旧两只。

### E. 游荡模式猎鼠（48 格）

`PetHuntMouseGoal extends NearestAttackableTargetGoal<Mouse>`：构造 `super(pet, Mouse.class, 10, true, false, null)`，重写 `getFollowDistance()` **返回常量 48**（必须返回常量——父类构造函数里就会调用它，此时子类实例字段尚未初始化）。`canUse()` 额外要求 `mode == WANDER && 已绑定`。
挂载于 `targetSelector.addGoal(0, ...)`（0 号，高于 `MouseSpawning` 现有的 1 号），按类名去重。

现有 [MouseSpawning.java](file:///c:/Users/15244/IdeaProjects/flavor_immersed_daily_argo/src/main/java/com/flavor_immersed_daily_argo/entity/MouseSpawning.java#L148-L155) 只给**猫**挂了 16 格猎鼠目标（`follow_range` 默认 16），且**无去重**——本方案新增的 goal 把范围扩到 48 格，并覆盖猫和狗。

## 八、验证方式

- 数据生成：`.\gradlew runData`（产物入 `src/generated/resources/`）
- 运行：`.\gradlew runClient`
- 游戏内核对：
  1. 创造模式 → **畜禽饲养** 横幅展开应共 **13** 件、末尾是宠物窝；若跑到「水产渔业」里说明计数没改。
  2. 放窝 → 破坏应掉落自身（验证 loot table）。
  3. `/summon cat` → 喂鱼驯服 → 附近有窝时约 2 秒内走向窝；`/data get entity` 可见 `NeoForgeData` 里出现窝坐标与 `Mode`。
  4. 空手右键：跟随 → 蹲下 → 游荡 → 跟随，动作栏中文正确；**手持染料右键仍能染项圈**（关键回归点）。
  5. 游荡模式下把主人拉远 40 格：宠物应留在窝周围约 24 格内，不跟过来。
  6. `/kill @e[type=cat]` → `/time add 24000` → 次日窝上出现同名、同项圈色、归属同一主人的猫。
  7. `/mouse spawn true` 在窝附近造老鼠 → 48 格内猫狗应直奔老鼠并扑到。
  8. 反复卸载/加载含宠物的区块 5 次，确认不累积重复 goal。

## 九、实现时需现场确认的点

1. `Component.Serializer.toJson(...)` 在 1.21.1 的确切签名（编译报错则改用等价重载）。
2. 方块贴图是否含透明像素 → 决定是否加 `"render_type": "minecraft:cutout"`。
3. 游荡中的猫是否会频繁跑去趴床 / 趴箱子（`CatSitOnBlockGoal(7)`、`CatLieOnBedGoal(5)` 优先级高于 10）。观感差则在 WANDER 模式额外移除这两个 goal，回到其它模式按原版数值加回。
4. 未绑定宠物进入游荡模式的限制（假设 2）——放开只需改 `cycleMode` 里一个判断。
